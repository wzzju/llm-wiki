# 10-inbox — 미처리 소스 진입점 (받은 편지함)

> **새 소스는 여기에 떨굽니다.** 이 폴더는 아직 위키에 통합 안 된 소스의 **대기열(흐름)**입니다. `/compile`이 처리하면 원본은 `20-raw/`(영구 보관)로 옮겨갑니다. 그래서 **inbox에 남아 있는 = 아직 컴파일 안 된 것**입니다.

## 데이터 넣는 법

1. 소스 파일을 이 폴더에 넣습니다 (직접 떨구거나 `/ingest <URL|파일>`로 자동 수집).
   - 형식: `.md` / `.txt` / `.pdf` (기사·논문·노트·전사본 등)
   - 파일명 권장: `YYYY-MM-DD-제목-슬러그.md`
   - 웹 기사면 본문을 복사해 `.md`로 저장하고, 출처 URL을 파일 안 맨 위에 적어둡니다.
   - 소스가 참조하는 이미지·figure는 `20-raw/assets/`에 직접 둡니다 (영구 자산 → 링크 안정).
2. Claude Code에서 `/compile`을 실행합니다 (위키화).
   - `/compile` (인자 없이) → inbox의 미컴파일 소스를 찾아 순서대로 위키화
   - `/compile 10-inbox/2026-06-19-article.md` → 특정 소스만
3. 처리가 끝나면:
   - 합성 결과는 `30-wiki/`에 페이지로 쌓이고(라우터·타입 인덱스·aliases 갱신),
   - **원본은 `20-raw/`로 자동 이동**되어 영구 보관(불변)됩니다.

## 규칙

- inbox는 **흐름(대기열)**, `20-raw/`는 **저장(영구 원본)**입니다 — 역할이 다릅니다.
- inbox에 파일이 남아 있으면 "할 일(미처리 소스)이 있다"는 신호입니다.
- 개인정보·비밀키가 든 문서는 넣기 전에 마스킹하세요 (`.gitignore`의 PII 블록 참조).
- inbox 자체는 LLM이 수정 대상으로 삼지 않습니다. 읽고 → 위키 합성 → raw로 이동만 합니다.
